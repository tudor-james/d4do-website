Hypervelocity Engineering on Rails

Loop engineering for the full development lifecycle — with humans firmly in the loop

Cosmogony is a collaborative agentic engineering platform that delivers software from business requirement to working, tested code — without taking over your process, your infrastructure, or your judgement.

This is loop engineering, not an autocomplete tool. A specialist AI agent runs at each stage of the pipeline. Every stage produces a durable document committed to the repository. The pipeline pauses at each gate and waits for you.

The Four-Stage Pipeline

Stage 1

Requirements

The requirements agent turns your brief into a structured specification, grounded in codebase context it has read.

Stage 2

Design

The design agent produces an architecture that aligns to your existing patterns and records decisions in a durable design document.

Stage 3

Planning

The planning agent decomposes the design into a concrete, ordered task list with vertical slices so the build stays always-green.

Stage 4

Development

The development agent builds slice by slice, running your build toolchain continuously. Done means the gate turns green — not agent self-report.

Every stage produces a durable document committed to the repository — requirements.md, design.md, plan.md — so the work survives any infrastructure restart and is fully auditable.

Human Gates Are Non-Negotiable

After each stage, the pipeline pauses and presents its output for your approval. You can approve and advance, reject and send it back for revision, or jump to any earlier stage. The agents never proceed past a gate without explicit sign-off.

This is the human-in-the-loop model taken seriously: not a checkbox, but a structural enforcement in the workflow engine. Stage state is persisted to the database — a backend restart or a container failure never loses your position or forces a re-run.

Gate classification is deterministic, not LLM-decided. When you respond to a gate, the platform classifies your message as approve or reject using a lightweight classifier — the routing decision is never left to the agent's interpretation. Ambiguous responses are treated as rejection (safe default), never as silent approval.

Completion Is Deterministic

"Done" is decided by a platform-controlled gate executor that runs your build, test, lint, and acceptance checks directly — not by asking the agent whether it thinks it finished. The agent cannot weaken or bypass these checks.

The platform owns the definition of done:

  • Build profiles are coded into the platform and versioned with deployments. No in-repo script can redefine what "test" means.
  • A hidden acceptance harness, invisible to the builder agent, runs the final gate. The agent cannot read or edit these tests — it cannot teach to the test.
  • A stage is only marked complete when the gate passes. LLM opinion is non-blocking commentary at most.
  • An inconclusive gate (infrastructure error, timeout) never counts as a pass. Failures surface to you with full context.

Context Comes From Files, Not History

Each agent turn starts from an empty session. Context is injected from predecessor documents on disk — the design agent reads requirements.md, the planning agent reads design.md and requirements.md, and so on. This eliminates the most common agentic failure mode: accumulated context from prior stages polluting the current agent's reasoning.

Git is the persistence boundary. The sandbox is ephemeral; anything that must survive a turn is committed and pushed. Your repository is the source of truth, not an in-memory state machine.

Teams Work Together in Shared Sessions

Multiple engineers can join the same agentic session in real time, see the same agent activity, and interact with the same workflow state. Collaboration is built into the session model. The agent activity feed shows which agent is active, what tools it has called, and what it produced — nothing happens in a black box.

Agents Run 24/7 in the Background

Once you approve a gate, work continues without you — long builds, test runs, multi-step implementations. Come back to a completed stage ready for your review, not a half-finished branch waiting for manual intervention. Agents are first-order team members. They have access to the same tools your engineers use: your git repo, your build pipeline, your issue tracker. They work on named branches, open pull requests, and update tickets.

Designed to Run to Completion

Cosmogony applies loop engineering discipline to prevent the failure modes that plague agentic systems: tool dispatch loops, agents that describe changes without executing them, stage skipping, and context exhaustion. Hard attempt caps, independent verification, and structured state ensure that when an agent is working, it is genuinely making progress — and when it hits a wall, it escalates to you with full context rather than looping silently.
